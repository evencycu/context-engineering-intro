# Database Schema Design

## 概述

本資料庫設計基於 Teams Notification 服務的需求，支援企業級的訊息發送、計費、監控和管理功能。

## 核心設計原則

1. **正規化設計**: 遵循第三正規化，減少資料冗餘
2. **可擴展性**: 支援大量用戶和通知的處理
3. **審計追蹤**: 完整的操作記錄和日誌
4. **效能優化**: 適當的索引和分區策略
5. **資料完整性**: 外鍵約束和檢查約束

## 資料表結構

### 核心業務表

#### 1. companies (公司表)
- 儲存公司/組織資訊
- 支援多租戶架構
- 包含計費設定

#### 2. users (用戶表)
- 系統用戶資訊
- 支援角色權限 (admin, user, viewer)
- API Key 管理

#### 3. notification_keys (通知金鑰表)
- 專案/通知金鑰管理
- 預先申請機制
- 配額限制設定

#### 4. destinations (目的地表)
- Teams 目標管理
- 支援多種目標類型 (person, channel, chatgroup)
- 驗證狀態追蹤

#### 5. notifications (通知表)
- 核心通知訊息
- 支援多種訊息類型 (text, file)
- 狀態追蹤

#### 6. notification_destinations (通知目的地關聯表)
- 多對多關聯
- 個別目的地狀態追蹤
- Teams 訊息 ID 記錄

### 進階功能表

#### 7. scheduled_notifications (排程通知表)
- 支援一次性排程
- 支援週期性排程 (Cron)
- 時區支援

#### 8. batch_notifications (批次通知表)
- 批次處理支援
- 進度追蹤
- 統計資訊

### 計費系統表

#### 9. billing_plans (計費方案表)
- 計費方案定義
- 價格設定
- 限制設定

#### 10. company_billing (公司計費表)
- 公司計費設定
- 付款方式
- 幣別設定

#### 11. usage_records (使用記錄表)
- 詳細使用記錄
- 計費計算基礎
- 週期性統計

### 審計和日誌表

#### 12. audit_logs (審計日誌表)
- 操作記錄
- 變更追蹤
- 安全審計

#### 13. system_logs (系統日誌表)
- 應用程式日誌
- 錯誤追蹤
- 效能監控

### 配置表

#### 14. system_settings (系統設定表)
- 系統參數
- 功能開關
- 公開設定

#### 15. feature_flags (功能開關表)
- 功能開關管理
- A/B 測試支援
- 公司級別控制

## 索引策略

### 主要索引
- 外鍵索引: 提升關聯查詢效能
- 狀態索引: 快速篩選狀態
- 時間索引: 支援時間範圍查詢
- 複合索引: 支援複雜查詢條件

### 特殊索引
- JSONB 索引: 支援 JSON 欄位查詢
- 部分索引: 針對特定條件的優化
- 覆蓋索引: 減少回表查詢
