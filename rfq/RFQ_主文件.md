## 1. 執行摘要

### 1.1 專案背景

本公司計劃建立一套企業級的 Microsoft Teams 通知服務系統，用於統一內部多個應用系統的通知流程。系統需支援多目標（頻道、群組、個人）訊息發送、預先註冊目的地管理、完整的監控計費功能，並符合企業級的安全性和可靠性要求。

### 1.2 專案目標

- 建立可擴展的 Teams 通知中台架構
- 整合 Microsoft Teams Bot Framework 與內部系統
- 提供完整的 RESTful API 供內外部系統調用
- 實現企業級的監控、計費和權限管理功能
- 支援高併發、高可用性的生產環境部署

### 1.3 專案範圍

本 RFQ 涵蓋以下範圍：

✅ **包含項目：**
- 完整的後端系統開發（Backend API Server）
- Database Schema 設計與實作（PostgreSQL）
- Cache 與 Queue 系統實作（Redis）
- Microsoft Teams Bot Framework 整合
- 完整的 API 文件（OpenAPI 3.0）
- 部署配置文件（Docker/Kubernetes）
- 單元測試與整合測試
- 系統文件與操作手冊
- 技術移交與培訓（4小時）

❌ **不包含項目：**
- 前端 UI 開發（本專案僅提供 API）
- Microsoft Teams Bot 申請與註冊（由本公司負責）
- 雲端基礎設施費用（由本公司負責）
- 生產環境維運支援（僅提供保固期支援）

## 2. 技術需求概述

### 2.1 系統架構

- **架構模式**: 微服務架構，採用 Actor Pattern 處理異步通知
- **開發語言**: Golang (Go 1.21+)
- **Web 框架**: Gin
- **主要資料庫**: PostgreSQL 14+
- **快取與佇列**: Redis 7+
- **部署方式**: Docker 容器化 + Kubernetes（支援 Docker Compose 開發環境）

### 2.2 核心功能模組

| 模組編號 | 模組名稱 | 功能描述 | 優先級 |
|---------|---------|---------|--------|
| M-001 | 公司與用戶管理 | 多租戶架構、用戶權限管理（RBAC） | P0 |
| M-002 | 專案管理 | Notification Key 管理、專案配額限制 | P0 |
| M-003 | Teams Bot 管理 | Bot 資訊管理、安裝追蹤 | P0 |
| M-004 | 目的地管理 | 預先註冊 Teams 目的地（頻道/群組/個人） | P0 |
| M-005 | 通知發送服務 | 同步/異步通知發送、廣播功能 | P0 |
| M-006 | 佇列與重試系統 | Redis 佇列、Actor Pool、自動重試、熔斷器 | P0 |
| M-007 | Token 管理 | Teams Token 快取、自動刷新 | P1 |
| M-008 | 計費系統 | 專案級計費、使用量統計 | P1 |
| M-009 | 監控與日誌 | 健康檢查、系統指標、結構化日誌 | P1 |
| M-010 | 外部 API | 簡化的外部調用 API（Provision、Notify） | P1 |

### 2.3 技術規格亮點

- **Rate Limiting 合規**: 符合 Microsoft Teams API 速率限制（50 RPS 全域、7 RPS 每對話）
- **高可用性設計**: 支援多實例部署、無狀態架構
- **重試機制**: 指數退避 + Teams Retry-After 智能處理
- **Actor Pattern**: 異步處理通知，支援並發控制
- **Two-loop Enqueue Design**: Producer 快速寫入、後台 Worker 批次入隊
- **Security**: JWT 認證、API Key、敏感資料加密

### 2.4 整合需求

- Microsoft Teams Bot Framework
- Microsoft Graph API (可選)
- Azure Entra ID (OAuth2/OIDC)
- 支援 Webhook 回調機制
