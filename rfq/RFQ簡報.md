# 2️⃣ 系統架構概述

---

## 技術架構

```
外部應用系統 (App A, B, C, 監控系統)
         ↓ REST API (HTTPS)
    API Gateway (Gin Server)
         ↓
   ┌──────┼──────┐
   ↓      ↓      ↓
Business Queue  Token
Services Actor  Cache
   ↓      ↓      ↓
   └──────┼──────┘
         ↓
  Data Layer (PostgreSQL + Redis)
         ↓
  Microsoft Teams API
```

---

## 關鍵技術特性

| 特性 | 技術實作 | 效益 |
|------|---------|------|
| **Two-loop Enqueue** | Producer 快速寫 DB + Worker 批次入隊 | API 延遲 < 5ms |
| **Actor Pool** | Goroutine Pool 管理並發 | 可控並發、防止資源耗盡 |
| **Token Cache** | Redis 快取 50min TTL | 減少 API 調用 95%+ |
| **Circuit Breaker** | 熔斷器保護 | 快速失敗、防止級聯故障 |

---

## 技術棧選型

| 類別 | 技術 | 版本 | 選擇理由 |
|------|------|------|---------|
| **程式語言** | Golang | 1.21+ | 高性能、併發優秀、記憶體效率高 |
| **Web 框架** | Gin | 1.9+ | 輕量、快速、生態成熟 |
| **資料庫** | PostgreSQL | 14+ | 關聯查詢強、JSONB 支援 |
| **快取/佇列** | Redis | 7+ | 高性能、持久化、支援多種資料結構 |
| **容器化** | Docker | 20+ | 標準化部署、易於擴展 |

**為什麼選擇 Golang？** 原生高併發、部署簡單、記憶體效率比 Java/Node.js 低 50%+

## 核心功能 1: 預先註冊機制 🔑

### Notification Key 映射流程

```
外部系統 → POST /api/v1/notify
           { "notifyKey": "project-alpha", 
             "targets": ["all"] }
           ↓
系統處理 → 1. 驗證 notifyKey
           2. 查詢預先註冊的目的地
           3. 展開 targets (all → 所有目的地)
           4. 批次發送通知
```

### 優點
✅ 安全可控（預先註冊）  
✅ 集中管理（IT 統一管理）  
✅ 權限隔離（專案隔離）  
✅ 審計追蹤（完整日誌）

---

## 核心功能 2: Two-loop Enqueue 設計 📊

### 三階段處理

```
1️⃣ Producer Loop (API)
   接收請求 → 快速寫入 DB → 回傳 202 Accepted
   ⏱️ 延遲: 1-5ms

2️⃣ Enqueue Worker (背景)
   掃描 pending → 推入 Redis → 按優先級排序

3️⃣ Consumer Loop (Actor Pool)
   BLPOP → Actor 處理 → 重試 + 熔斷器 → sent/failed
```

**關鍵優勢**: 低延遲 + 高吞吐 + 可靠性 + 可觀測性

---

## 核心功能 3: 智能重試機制 🔄

### 指數退避策略

| 重試次數 | 等待時間 | 累計時間 |
|---------|---------|---------|
| 第 1 次失敗 | 1 秒 | 1 秒 |
| 第 2 次失敗 | 2 秒 | 3 秒 |
| 第 3 次失敗 | 4 秒 | 7 秒 |
| 第 4 次失敗 | 8 秒 | 15 秒 |
| 第 5 次失敗 | 16 秒 | 31 秒 |

**特殊處理**: 429 Rate Limit → 讀取 Retry-After header

### 熔斷器保護 🔌
Closed → (5 次失敗) → Open (30 秒) → Half-Open → Closed/Open
