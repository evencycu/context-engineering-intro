## 第一條：合約標的

甲方委託乙方開發「Microsoft Teams 企業級通知服務系統」（以下簡稱「本系統」），乙方同意依本合約規定完成開發、測試、部署及移交等工作。

---

## 第二條：專案範圍

### 2.1 包含項目

乙方應完成以下工作：

1. **系統開發**
   - 完整後端 API Server 開發（Golang）
   - Database Schema 設計與實作（PostgreSQL）
   - Cache 與 Queue 系統實作（Redis）
   - Microsoft Teams Bot Framework 整合
   - 完整測試（單元測試、整合測試）

2. **文件交付**
   - 完整的 API 文件（OpenAPI 3.0 規範）
   - 系統架構文件
   - 資料庫設計文件（ERD）
   - 部署指南
   - 操作手冊
   - 測試報告

3. **部署配置**
   - Docker 映像檔
   - Docker Compose 配置
   - Kubernetes 部署檔案

4. **技術移交**
   - 4 小時技術培訓（可分 2 次進行）
   - 程式碼走讀與說明
   - Q&A 與問題討論

### 2.2 排除項目

以下項目不在本合約範圍內：

- ❌ 前端 UI 開發
- ❌ Microsoft Teams Bot 申請與註冊
- ❌ 雲端基礎設施租用費用
- ❌ 生產環境維運支援（保固期後）

---

## 第三條：驗收標準

### 3.1 功能驗收

系統應通過以下功能測試（100% 通過）：

1. 公司、用戶、專案 CRUD 操作
2. Bot 管理與目的地註冊
3. 通知發送（文字、Adaptive Card）
4. 廣播功能（多目標發送）
5. 外部 API 調用（/api/v1/notify、/api/v1/destinations）

### 3.2 性能驗收

系統應達到以下性能指標：

| 指標 | 目標值 |
|------|-------|
| API 響應時間 (P95) | < 500ms |
| API 響應時間 (P99) | < 1000ms |
| 通知發送成功率 | ≥ 99% |
| 併發請求支援 | ≥ 100 req/s |

### 3.3 程式碼品質

- 測試覆蓋率 ≥ 70%
- 符合 Go 官方程式碼風格
- 無 Critical/High 級別的已知 Bug

### 3.4 部署驗收

- Docker 映像可成功建置
- Docker Compose 環境可正常啟動
- Kubernetes 配置可成功部署
- 健康檢查端點正常回應

---

## 第四條：專案時程與里程碑

### 4.1 專案時程

預計專案期程為 **14 週**，分為以下階段：

| 階段 | 工期 | 里程碑 |
|------|------|--------|
| Phase 1: 需求確認 | 1 週 | M1: 需求規格書簽署 |
| Phase 2: 系統設計 | 2 週 | M2: 設計審查通過 |
| Phase 3: 開發實作 | 8 週 | M3: Alpha 版本交付 |
| Phase 4: 測試與優化 | 2 週 | M4: Beta 版本交付 |
| Phase 5: 部署與移交 | 1 週 | M5: 正式驗收通過 |

### 4.2 延遲罰則

若乙方未能依約定時程完成，應按以下標準支付延遲違約金：

- 延遲 1-7 天：合約總價 1%
- 延遲 8-14 天：合約總價 3%
- 延遲 15-30 天：合約總價 5%
- 延遲超過 30 天：甲方得解除合約，乙方應退還已收款項並賠償損失

**例外情況**：因甲方原因導致延遲，不計入乙方延遲天數。
